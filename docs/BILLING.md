# ConveneCore billing
Operator-owned invoices with explicit currency, total and duration, immutable invoice and receipt identifiers, transaction reference deduplication, and renewal publication to the existing entitlement system. No prices are hard-coded. Existing subscriptions are not changed merely by creating invoices. The operator may record independently verified external settlements; the application never collects card data or initiates a real payment. Sandbox invoices cannot extend real subscription expiry. There is no live gateway endpoint in this release.

The optional Pesapal API 3 sandbox adapter reads CC_PESAPAL_SANDBOX_KEY, CC_PESAPAL_SANDBOX_SECRET, CC_PESAPAL_SANDBOX_IPN_ID and CC_PESAPAL_SANDBOX_CALLBACK from the operator environment. Use a dedicated test merchant, registered sandbox IPN, and test-only callback. The console can create a sandbox checkout and query the gateway directly. No public IPN receiver is installed; operator-run reconcile_billing.py polls outstanding sandbox orders. Browser redirects are not trusted as proof of settlement. Verify exact merchant reference, amount, currency and completed status. Never use real customer payment details in a sandbox.

Manual external payment reconciliation requires operator confirmation based on a genuine independent payment record. Renewal extends from the next day after an existing inclusive expiry or today if expired; calendar months are used. A paid transaction is persisted before the entitlement file is published. A pending publication can be retried without extending the subscription again. No automatic refund handling, partial payments, tax calculation, public checkout, invoice emails or live payment processing. Printed HTML invoices and receipts are not tax invoices unless the operator has independently satisfied applicable requirements. Sandbox documents are marked test only. Keep the private registry backed up. Do not publish the operator console.

Run python -m unittest discover -s deploy -p "test_*.py" -v. Use disposable test data only. Live provider verification, production credentials, merchant onboarding and payment compliance require a separate authorized production release.
