# ConveneCore billing

The private SaaS administrator console supports production Yo! Uganda and ioTec Pay mobile-money collections. No other gateway is included. Configure gateways in the operator console: Yo API username/password; ioTec client ID, client secret and wallet ID. Each is disabled until explicitly enabled. Credentials are write-only in the browser, stored separately in a mode-0600 operator-owned file (not encrypted at rest), never copied to tenant workspaces, never committed to GitHub. Keep the console private via SSH tunnel; do not expose it publicly. Use dedicated collection-only merchant permissions and protect host backups. No payment PIN or OTP is collected.

Production URLs are fixed; TLS verification is enabled; redirects are rejected. Yo connection test is a balance request, ioTec connection test requests an OAuth token (not a wallet permission guarantee). No money moves during tests. Production collections use UGX only, with explicit operator confirmation of the payer's consent and amount. No automatic retries or fallback collection: an uncertain submission remains locked for reconciliation using its unique invoice reference. Status checks never initiate a collection.

Each operator-issued invoice records a fixed amount, plan and duration. A directly verified successful collection must match the invoice amount, currency, and gateway transaction identity; ioTec additionally verifies wallet, category and external ID. A settlement is persisted before renewal publication. Repeated verification cannot extend the subscription twice. Manual settlement requires independent evidence and operator confirmation. Sandbox/test invoices never extend real subscription dates. Renewals extend from the next unexpired day or today, in calendar months. Receipts are printable HTML, not statutory tax invoices. No prices or tax rates are assumed.

Run reconcile_billing.py on the trusted operator host to verify existing pending collections and publish pending renewals. A separate customer checkout worker and systemd timer are now provided; neither is installed yet. No public callback receiver is required for polling. A timeout or unresolved transaction needs provider-side reconciliation; do not submit a second charge. Provider reversals, refunds, partial payments, live end-to-end tests remain outstanding. Do not enable a real merchant until the operator has verified provider permissions, fee treatment, credentials and response contracts. The implementation is committed only to the development branch.


## Customer checkout
Set CC_CHECKOUT_INBOX and CC_CHECKOUT_ORIGIN in the private platform console environment. Issue a link for an open UGX invoice with at least one enabled gateway. Copy the one-time-displayed URL and deliver it privately to the authorized customer. A link is a seven-day bearer capability, not an authenticated customer account; it exposes only that invoice and its payment status. Revoke an unused link before replacing it or using operator settlement. The customer confirms the amount and mobile number, then approves the provider prompt on their own phone. The public process never has gateway secrets or access to the registry. It queues one request per invoice, and the worker revalidates against the private registry (token digest, expiry, amount, currency, provider and consent) before collection. Queue intents expire after 15 minutes; phone and token are removed when processed. Public projection data is not authoritative for settlement. A compromised public process could misuse a link it observes, so apply HTTPS, strict permissions, patching, rate limits and monitoring.

Deploy the public listener as an unprivileged account with access only to the separate inbox directory, not the operator registry, Docker socket or gateway credentials. Provision a dedicated checkout origin and exact Host forwarding; disable access logs for checkout URLs (tokens), HTTPS only, 4 KiB request cap, external request rate limits. Set a private directory and group permissions for the checkout SQLite file and journal (shared only between operator and checkout service). Use the provided example systemd units, adapting service accounts, paths and group permissions to the host; use a trusted operator account for the private worker. Keep the public service unprivileged. The timer runs 30 seconds after the preceding job completes; pending status checks back off from 30 seconds to 15 minutes. Registry locking serializes operator and worker actions; no charge retries occur. Pending or ambiguous transactions remain locked until reconciled. Paid records display receipt ID and renewed expiry in checkout; receipt email and customer portal integration are not included. A suspended stack is not automatically restarted when paid; renewal updates entitlement only. No real payment or service deployment is performed by this change.
