# Subscription enforcement

Managed tenants receive a read-only operator-owned subscription policy mounted into the backend and worker. The policy is tenant-specific; unavailable, invalid or mismatched policies fail closed. The platform console publishes updates atomically to a directory mount (not a single file mount), so upgraded running workspaces see renewal and plan changes on subsequent checks without restart. Existing managed deployments must be recreated once with the new mount before enforcement applies. Legacy standalone deployments intentionally remain unaffected.

## Expiry and renewals
Expiry is inclusive through the specified UTC date. The configurable grace period is 0–30 days; normal operations continue within grace. After grace, new writes and AI processing are rejected (HTTP 402), while authorized reads remain subject to module permissions. Account setup/recovery, meeting end/leave, and selected cleanup operations are permitted. Renew by editing the expiry in the platform console. No automatic payment or automatic shutdown is implemented. Blank expiry means no expiration configured. Existing data is not deleted on expiry or downgrade. In-flight requests/provider calls may finish.

## Seats, storage and AI
Seat limit counts all active users, including admins and minute secretaries. New staff and account reactivation acquire a transaction-scoped PostgreSQL advisory lock before checking the cap. Deactivation releases a seat. Guest attendees do not count as accounts.

Retained storage uses actual bytes beneath the workspace storage directory (recordings, logos, finalized documents, backups), and a shared filesystem lock serializes admission. Temporary uploads, audio normalization and backup generation outside the retained directory, PostgreSQL data, Redis, and container layers are not included. This is an application retained-file quota, not a host filesystem quota; production still needs infrastructure disk and temporary-file caps. Managed recordings are currently retained without the existing WebM compression step to avoid unbudgeted duplicate files. Replacements conservatively require room for the new file before deleting the previous file. Existing over-limit workspaces may delete files, but cannot add retained bytes until below cap.

Monthly AI allowance is a UTC calendar-month ledger. Audio is charged the ceiling of actual normalized audio seconds before provider upload; each text generation attempt is one allowance minute. Each retry is charged again. Failed attempted provider operations remain charged; no provider-cost or token-based billing is claimed. Ledger writes are serialized with PostgreSQL advisory locks; provider calls fail before exceeding the configured allowance. A new month uses a separate ledger key. The worker checks policy again before processing. Mock transcription is not charged. Offline restore must preserve the latest monthly ledger to prevent usage rollbacks.

Feature switches guard API routes and AI/worker paths for live meetings, recording, AI, custom formats, exports, action tracking, audit/backups. Public blank templates and existing structured minute reads remain available. Disabled modules may still have historical records displayed through other meeting views. This is a feature entitlement, not an additional record confidentiality boundary. Direct WebRTC media between already connected peers cannot be forcibly disconnected by an API policy update; signaling requests are denied.

## Verification
Unit tests cover policy validation, expiry/grace/renewal, feature routes, and tenant-specific policy publishing. Backend tests cover quota denials and the ledger. Run the full backend suite and two-tenant staging suite against PostgreSQL and verify concurrent seat/AI reservations, quota behavior, and policy updates before release. Customer subscription page is read-only. Billing, provider-cost reporting, and live production deployment remain separate.
